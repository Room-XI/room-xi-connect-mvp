## Task 6 – Recalculate age from DOB on login (guardian gating)

We want guardian gating decisions based on **current age**, not just age captured at signup.

### 6.1 Ensure DOB is loaded on login

Open `server/routes/auth.*` and find the `POST /login` handler.

You should see a query fetching user + profile:

```ts
const [user] = await db
  .select({
    id: users.id,
    email: users.email,
    passwordHash: users.passwordHash,
    profile: profiles, // includes age, dateOfBirth
  })
  .from(users)
  .leftJoin(profiles, eq(profiles.userId, users.id))
  .where(eq(users.email, email))
  .limit(1);
```

Make sure `profiles.dateOfBirth` is part of `profile` (it will be if `profile: profiles` is used).

### 6.2 Use calculateAge helper

You likely already have a `calculateAge` helper from signup. If not, define it near the top:

```ts
function calculateAge(dateOfBirth: string | Date | null): number | null {
  if (!dateOfBirth) return null;
  const dob = new Date(dateOfBirth);
  if (Number.isNaN(dob.getTime())) return null;

  const today = new Date();
  let age = today.getFullYear() - dob.getFullYear();
  const m = today.getMonth() - dob.getMonth();
  if (m < 0 || (m === 0 && today.getDate() < dob.getDate())) {
    age--;
  }
  return age;
}
```

### 6.3 Recompute age in login handler

After verifying the password but before setting `requiresGuardianVerification`:

```ts
let computedAge = user.profile?.age ?? null;

if (user.profile?.dateOfBirth) {
  const newAge = calculateAge(user.profile.dateOfBirth);
  if (newAge !== null) {
    computedAge = newAge;

    // Optionally persist updated age
    if (!user.profile.age || user.profile.age !== newAge) {
      await db
        .update(profiles)
        .set({ age: newAge })
        .where(eq(profiles.userId, user.id));
    }
  }
}
```

Then use `computedAge` for guardian gating:

```ts
const requiresGuardianVerification =
  computedAge !== null && computedAge < 16 && !guardianVerified;
```

Finally, store it in the session:

```ts
req.session.age = computedAge;
req.session.requiresGuardianVerification = requiresGuardianVerification;
```

This keeps behaviour consistent but avoids permanently treating someone as <16 if they’ve had a birthday.

## Task 8 – Add a moderation wrapper for Ximi (no text in logs)

We’ll add a small moderation helper to flag risky content **before** sending it to chat completions.

### 8.1 Create `server/services/moderation.ts`

```ts
import OpenAI from "openai";

const openai = new OpenAI({
  apiKey: process.env.AI_INTEGRATIONS_OPENAI_API_KEY!,
  baseURL: process.env.AI_INTEGRATIONS_OPENAI_BASE_URL,
});

export async function moderateText(
  text: string
): Promise<{ flagged: boolean; categories: Record<string, boolean> }> {
  if (!text || text.trim().length === 0) {
    return { flagged: false, categories: {} };
  }

  const result = await openai.moderations.create({
    model: "omni-moderation-latest",
    input: text,
  });

  const moderationResult = result.results?.[0];

  const flagged = moderationResult?.flagged ?? false;
  const categories = moderationResult?.categories ?? {};

  if (process.env.NODE_ENV !== "production") {
    console.log("[Moderation] debug", { flagged, categories });
  } else {
    // Production: log only booleans & categories (no text)
    console.log("[Moderation] summary", { flagged, categories });
  }

  return { flagged, categories };
}
```

> **Note:** This satisfies the requirement: *“log only boolean flags (flagged, categories) — not the text.”*

### 11.2 Scheduler helper to send reminders

Open `server/services/scheduler.js`.

```js
import { sql } from "drizzle-orm";
import { sendGuardianVerificationEmail } from "./parentInvite"; // adjust path
```

Add a new function:

```js
async function sendGuardianReminders() {
  const sevenDaysAgo = sql`NOW() - INTERVAL '7 days'`;

  const pending = await db.execute(sql`
    SELECT id, user_id, guardian_contact_type, guardian_contact_value, verification_token
    FROM guardian_verifications
    WHERE verified_at IS NULL
      AND created_at <= ${sevenDaysAgo}
      AND reminder_sent_at IS NULL
      AND expires_at > NOW()
  `);

  for (const row of pending.rows) {
    try {
      await sendGuardianVerificationEmail({
        userId: row.user_id,
        guardianContactType: row.guardian_contact_type,
        guardianContactValue: row.guardian_contact_value,
        token: row.verification_token,
        mode: "reminder", // update email copy/template accordingly
      });

      await db.execute(sql`
        UPDATE guardian_verifications
        SET reminder_sent_at = NOW()
        WHERE id = ${row.id}
      `);
    } catch (err) {
      console.error("[GuardianReminder] Failed to send reminder", {
        id: row.id,
        error: err,
      });
    }
  }
}
```

In the main scheduler tick (where other daily jobs are called), ensure `sendGuardianReminders()` is called **once per day**, e.g., in the same block as `runDataRetentionCleanup()`.

## Task 12 – Lightweight observability hook (OpenTelemetry, anonymized)

### 12.2 Create `server/otel.js`

```js
import { NodeSDK } from "@opentelemetry/sdk-node";
import { getNodeAutoInstrumentations } from "@opentelemetry/auto-instrumentations-node";
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-http";

const exporter = new OTLPTraceExporter({
  // Use env variable, e.g. OTEL_EXPORTER_OTLP_ENDPOINT
  // endpoint: process.env.OTEL_EXPORTER_OTLP_ENDPOINT,
});

const sdk = new NodeSDK({
  traceExporter: exporter,
  instrumentations: [
    getNodeAutoInstrumentations({
      "@opentelemetry/instrumentation-http": {
        enabled: true,
        ignoreIncomingRequestHook: (req) => {
          // Optionally ignore health endpoints
          return req.url?.startsWith("/health") || req.url?.startsWith("/api/health");
        },
      },
    }),
  ],
});

sdk
  .start()
  .then(() => {
    console.log("[OTel] Tracing initialized");
  })
  .catch((err) => {
    console.error("[OTel] Error initializing tracing", err);
  });
```

### 12.3 Load OTel conditionally in `server/index.js`

At the very top of `server/index.js`:

```js
if (process.env.ENABLE_OTEL === "true") {
  await import("./otel.js");
}
```

This ensures:

* By default (without `ENABLE_OTEL=true`), OTel is off.
* When enabled, we get anonymized traces.

### 12.4 Privacy notes

* Do **not** add custom span attributes with user text.
* Let auto-instrumentation record only:

  * HTTP method
  * path templates
  * status codes
* Avoid capturing full URLs that may contain IDs; if needed, configure instrumentation accordingly.

```ts
  crisisDetectedDelta = 0,
  moderationFlaggedDelta = 0,
}: {
  totalMessagesDelta?: number;
  crisisDetectedDelta?: number;
  moderationFlaggedDelta?: number;
}) {
  const today = sql`CURRENT_DATE`;

  await db.execute(sql`
    INSERT INTO ai_transparency_metrics (date, total_messages, crisis_detected, moderation_flagged)
    VALUES (${today}, ${totalMessagesDelta}, ${crisisDetectedDelta}, ${moderationFlaggedDelta})
    ON CONFLICT (date) DO UPDATE
      SET total_messages = ai_transparency_metrics.total_messages + ${totalMessagesDelta},
          crisis_detected = ai_transparency_metrics.crisis_detected + ${crisisDetectedDelta},
          moderation_flagged = ai_transparency_metrics.moderation_flagged + ${moderationFlaggedDelta}
  `);
}
```

### 14.4 Admin endpoint to read transparency metrics

In `server/routes/analytics.ts` (or a new `server/routes/aiTransparency.ts`), add:

```ts
analyticsRouter.get("/ai-transparency", async (req, res) => {
  try {
    const rows = await db.execute(sql`
      SELECT
        date,
        total_messages,
        crisis_detected,
        moderation_flagged
      FROM ai_transparency_metrics
      WHERE date >= CURRENT_DATE - INTERVAL '30 days'
      ORDER BY date ASC;
    `);

    const data = rows.rows.map((row: any) => ({
      date: row.date.toISOString().slice(0, 10),
      totalMessages: row.total_messages,
      crisisDetected: row.crisis_detected,
      moderationFlagged: row.moderation_flagged,
    }));

    return res.json({ data });
  } catch (err) {
    console.error("[Analytics] ai-transparency error", err);
    return res.status(500).json({ error: "Failed to load AI transparency metrics" });
  }
});
```

Admin dashboard can then chart:

* total Ximi messages by day,
* crisis detections by day,
* moderation flags by day.
