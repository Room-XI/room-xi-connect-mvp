## Task 6 – Recalculate age from DOB on login (better guardian gating)

Right now age might be stored once at signup; we want to recalc from DOB at login so youth who turn 16 aren’t stuck.

1. Open the auth routes file (e.g. `server/routes/auth.*`).

2. Locate the `POST /login` handler.

3. Make sure the login user query selects:

   * `users.id`, `users.email`, `users.passwordHash`
   * joined `profiles` with at least `profiles.age` and `profiles.dateOfBirth` if available.

4. After password verification, compute `computedAge`:

   ```ts
   let computedAge = user.profile?.age ?? null;

   if (user.profile?.dateOfBirth) {
     const newAge = calculateAge(user.profile.dateOfBirth); // reuse your existing helper
     if (newAge !== null) {
       computedAge = newAge;

       // Optionally persist updated age if changed
       if (!user.profile.age || user.profile.age !== newAge) {
         await db
           .update(profiles)
           .set({ age: newAge })
           .where(eq(profiles.userId, user.id));
       }
     }
   }
   ```

5. When computing `requiresGuardianVerification`, use `computedAge`:

   ```ts
   const requiresGuardianVerification =
     computedAge !== null && computedAge < 16 && !guardianVerified;
   ```

6. When setting the session, store:

   ```ts
   req.session.age = computedAge;
   req.session.requiresGuardianVerification = requiresGuardianVerification;
   ```

This keeps the logic the same, but base it on real age, not a stale snapshot.

## Task 8 – Add a simple moderation wrapper for Ximi

We’ll add a small moderation helper that can block or soften extremely risky content before calling OpenAI chat completions.

1. Create `server/services/moderation.ts`:

   ```ts
   import OpenAI from "openai";

   const openai = new OpenAI({
     apiKey: process.env.AI_INTEGRATIONS_OPENAI_API_KEY!,
     baseURL: process.env.AI_INTEGRATIONS_OPENAI_BASE_URL,
   });

   export async function moderateText(text: string): Promise<{ flagged: boolean; categories: Record<string, boolean> }> {
     if (!text || text.trim().length === 0) {
       return { flagged: false, categories: {} };
     }

     const result = await openai.moderations.create({
       model: "omni-moderation-latest",
       input: text,
     });

     const moderationResult = result.results?.[0];
     return {
       flagged: moderationResult?.flagged ?? false,
       categories: moderationResult?.categories ?? {},
     };
   }
   ```

2. In `server/services/ximi.*`, import it:

   ```ts
   import { moderateText } from "./moderation";
   ```

3. At the top of your `generateXimiResponse` (or equivalent), **after** crisis keyword detection but **before** calling OpenAI chat completions:

   ```ts
   const moderation = await moderateText(userMessage);
   if (moderation.flagged) {
     // We will also log this in a privacy-safe way in Task 15
     return {
       message: "I'm not able to continue with that topic, but I'm still here to talk about how you're feeling.",
       crisisDetected: false,
       crisisKeywords: [],
     };
   }
   ```

This adds a second safety net alongside your crisis keyword rules and system prompts.

### 11.2 Add reminder job to scheduler

Open `server/services/scheduler.js`.

1. Add a helper function:

   ```js
   async function sendGuardianReminders() {
     const sevenDaysAgo = sql`NOW() - INTERVAL '7 days'`;

     const pending = await db.execute(sql`
       SELECT id, user_id, guardian_contact_type, guardian_contact_value, verification_token
       FROM guardian_verifications
       WHERE verified_at IS NULL
         AND created_at <= ${sevenDaysAgo}
         AND reminder_sent_at IS NULL
         AND expires_at > NOW()
     `);

     for (const row of pending.rows) {
       try {
         await sendGuardianVerificationEmail({
           userId: row.user_id,
           guardianContactType: row.guardian_contact_type,
           guardianContactValue: row.guardian_contact_value,
           token: row.verification_token,
           mode: "reminder", // adjust your email template logic
         });

         await db.execute(sql`
           UPDATE guardian_verifications
           SET reminder_sent_at = NOW()
           WHERE id = ${row.id}
         `);
       } catch (err) {
         console.error("[GuardianReminder] Failed to send reminder", { id: row.id, error: err });
       }
     }
   }
   ```

   Adjust function and column names to match your real code (e.g. if `sendGuardianVerificationEmail` already exists).

2. In the main scheduler tick (where you run other daily jobs), call `sendGuardianReminders()` **once per day** (e.g. in the same block as data-retention cleanup).

This will resend **one** reminder after 7 days and then stop.

### 12.2 Create an OTel bootstrap file

Create `server/otel.js`:

```js
import { NodeSDK } from "@opentelemetry/sdk-node";
import { getNodeAutoInstrumentations } from "@opentelemetry/auto-instrumentations-node";
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-http";

const exporter = new OTLPTraceExporter({
  // Read OTLP endpoint from env, e.g. OTEL_EXPORTER_OTLP_ENDPOINT
});

const sdk = new NodeSDK({
  traceExporter: exporter,
  instrumentations: [
    getNodeAutoInstrumentations({
      "@opentelemetry/instrumentation-http": {
        enabled: true,
        // Avoid capturing full URLs with IDs in span names
        ignoreIncomingRequestHook: (req) => {
          // you can ignore health endpoints if you want
          return req.url?.startsWith("/health");
        },
      },
    }),
  ],
});

sdk.start().then(() => {
  console.log("[OTel] Tracing initialized");
}).catch((err) => {
  console.error("[OTel] Error initializing tracing", err);
});
```

### 12.4 Privacy guardrails

* Use only high-level attributes like:

  * HTTP route template (if available)
  * status code

  * `route.guardianGated = true/false`

Leave sampling at the default, or configure a low rate if you add it.

## Task 14 – AI transparency logs (counts only)

### 14.2 Add a helper to increment metrics

Create `server/services/aiTransparency.ts`:

```ts
import { db } from "../db";
import { aiTransparencyMetrics } from "../schema";
import { sql } from "drizzle-orm";

export async function recordAiMetrics({
  totalMessagesDelta = 0,
  crisisDetectedDelta = 0,
  moderationFlaggedDelta = 0,
}: {
  totalMessagesDelta?: number;
  crisisDetectedDelta?: number;
  moderationFlaggedDelta?: number;
}) {
  const today = sql`CURRENT_DATE`;

  await db.execute(sql`
    INSERT INTO ai_transparency_metrics (date, total_messages, crisis_detected, moderation_flagged)
    VALUES (${today}, ${totalMessagesDelta}, ${crisisDetectedDelta}, ${moderationFlaggedDelta})
    ON CONFLICT (date) DO UPDATE
      SET total_messages = ai_transparency_metrics.total_messages + ${totalMessagesDelta},
          crisis_detected = ai_transparency_metrics.crisis_detected + ${crisisDetectedDelta},
          moderation_flagged = ai_transparency_metrics.moderation_flagged + ${moderationFlaggedDelta}
  `);
}
```

### 14.3 Call helper from Ximi routes

In `server/routes/ximi.*` (or in `server/services/ximi.*`), after each successful chat request:

* Call `recordAiMetrics({ totalMessagesDelta: 1 })`.
* If a crisis keyword path was triggered (crisis detection), also add `crisisDetectedDelta: 1`.
* When moderation flags a message (Task 8), also call `recordAiMetrics({ moderationFlaggedDelta: 1 })`.

### 14.4 Admin endpoint for transparency
