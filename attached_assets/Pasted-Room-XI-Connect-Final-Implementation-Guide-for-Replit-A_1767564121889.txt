Room XI Connect: Final Implementation Guide for Replit AI

Objective: This document provides a complete, step-by-step guide for Replit AI to implement all necessary fixes and features to make Room XI Connect launch-ready. This includes security hardening, compliance fixes, and the implementation of game-changing features.

Guiding Principles:

•
Execute Sequentially: Follow each step in order. Do not proceed until the validation for the current step passes.

•
No New Costs: All changes use the existing tech stack.

•
No New Keys: Use existing environment variables where possible. New keys are specified in the .env.example changes.

•
Self-Contained: This guide is designed to be executed without external clarification.




Phase 1: Critical Fixes & Compliance (2-3 Days)

Step 1.1: Apply Patch for Auth & Admin Fixes

Action: The provided patch fixes critical issues with password resets, parent invites, and admin portal authentication. It also adds necessary database migrations and documentation.

Instructions:

1.
Apply the git patch from pasted_content_3.txt to your codebase.

2.
Fix the import collision in server/routes/auth.js. Ensure eq is imported only once from drizzle-orm.

3.
Adjust getPublicUrl() usage in server/services/parentInvite.ts. Use the PUBLIC_URL environment variable instead of calling the utility function without a request object.

Validation:

1.
Run pnpm install to ensure all dependencies are met.

2.
Run pnpm run db:migrate to apply the new database migrations.

3.
Run pnpm run typecheck to confirm there are no TypeScript errors.

4.
Start the server with pnpm run dev and confirm it runs without crashing.

Step 1.2: Implement Email Plus Consent Flow

Action: Replace the non-compliant, one-click email verification with a legally defensible, two-step "Email Plus" consent flow.

Instructions:

1.
Follow the detailed instructions in the replit_ai_implementation_guide.md (provided previously) for Phase 1: Foundational Compliance (Email Plus & Audit Trail).

2.
This includes:

•

Validation:

Step 1.3: Complete the Parent Portal

Action: Add the missing consent management features to the parent portal.

Instructions:

1.
Consent Withdrawal:

•
Create a new endpoint: POST /api/parent/consent/withdraw

•
This endpoint should update the consents table, setting value to false for the specified consent type.

•
Add a "Withdraw" button in the ParentConsentManager.tsx component that calls this endpoint.

•
When consent is withdrawn, the youth should be logged out and their access restricted until consent is re-granted.



2.
Data Download:

•
Create a new endpoint: GET /api/parent/data/export

•
This endpoint should query all data related to the youth (profile, check-ins, attendance, etc.) and compile it into a CSV file.

•
Use the json2csv library (already a dependency) to generate the CSV.

•
Add a "Download All Data" button in the ParentPortal.tsx that triggers this download.



3.
Data Deletion Request:

•
Create a new endpoint: POST /api/parent/data/delete

•
This endpoint should flag the user for deletion and notify an admin. Do not delete immediately.

•
Add a "Request Permanent Deletion" button in the ParentPortal.tsx that calls this endpoint.



Validation:

1.
Log in as a parent and successfully withdraw consent for a youth.

2.
Confirm the youth is logged out and cannot log back in.

3.
Successfully download a CSV of the youth's data.

4.
Successfully request data deletion and confirm an admin is notified.




Phase 2: Game-Changing Features (3-4 Days)

Step 2.1: Implement SMS/WhatsApp Consent Sharing

Action: Add the ability for youth to send consent links to their parents via SMS.

Instructions:

1.
Integrate Twilio:

•
Add twilio to your package.json dependencies.

•
Add TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, and TWILIO_PHONE_NUMBER to your .env.example and Replit Secrets.



2.
Backend:

•
Create a new endpoint: POST /api/consent/send-sms

•
This endpoint should generate a one-time use token and send an SMS with the consent link.



3.
Frontend:

•
On the consent waiting screen, add a "Send a text instead?" button.

•
When clicked, show a form for the parent's phone number.

•
Call the /api/consent/send-sms endpoint.



Validation:

1.
Register as a new youth under 16.

2.
Use the "Send a text instead?" feature.

3.
Confirm an SMS is received with a valid, one-time use link.

4.
Complete the consent flow via the SMS link.
