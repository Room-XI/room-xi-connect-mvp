2) CORS is incorrect / unsafe-by-default (MUST FIX)

A) Wildcard logic for subdomains is broken
	•	File: server/middleware/cors.ts
	•	Issue: This block breaks matching for https://*.replit.dev:

if (allowed.includes('*.')) {
  const wildcardPattern = allowed.replace('*.', '([a-zA-Z0-9-]+\\.)+');
  const regex = new RegExp(`^${wildcardPattern.replace(/\./g, '\\.')}$`);
  return regex.test(origin);
}

The second .replace(/\./g, '\\.') also escapes the dots inside the injected ([a-zA-Z0-9-]+\.)+ group → the regex won’t match real origins.

	•	Fix required (recommended):
	•	Don’t regex-escape strings like this.
	•	Parse origin with new URL(origin) and match host suffix (e.g., hostname.endsWith('.replit.dev')).
	•	Add Vary: Origin header when allowing origins.

B) Production behavior should not silently allow localhost
	•	File: server/middleware/cors.ts
	•	Issue: If ALLOWED_ORIGINS is empty, you push:
	•	http://localhost, http://localhost:5000, http://localhost:5173, etc.
	•	plus Replit domains from REPLIT_DOMAINS / REPLIT_DEV_DOMAIN
	•	Fix required:
	•	In production, if ALLOWED_ORIGINS is empty → fail fast (log + throw).
	•	Keep localhost defaults only for development/test.

What to set on Replit (prod):
	•	Set ALLOWED_ORIGINS to your deployed web origin(s), comma-separated:
